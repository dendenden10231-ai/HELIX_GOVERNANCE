01 The thesis

One rule, from which the whole system is derived

The language model is permitted to read and to name. It is forbidden to compute and to decide. Every number, every threshold, every verdict is produced by deterministic Python whose source is open to line-by-line inspection.

This is not an aspiration written in documentation. It is enforced inside the system prompt sent to the model on every single call. Here it is verbatim, from the running file:

helix_pipeline/engine/governance_classifier.pysystem prompt · verbatim from §16 of the specification
1. HALLUCINATIONS: identify signals of 7 types (TYPE-1..TYPE-7). Return ONLY text labels and excerpts — NOT numbers. The mathematics (severity weights, confidence) is computed by the Python engine. 2. NGI DIMENSIONS: score 4 dimensions on a 0-3 scale. These are the ONLY numbers you return. Justify in prose, without formulas. IMPORTANT: - Do not include confidence numbers, scores, weights — that is the engine - Do not include governance_decision — that is the engine - severity_signal is your semantic reading only, not a final weight
What matters here. The model returns exactly four numbers per pass — four 0–3 ratings on a narrative-gravity scale. Everything else, including the final verdict of pass / escalate to a human / block, it is structurally unable to utter. The prompt is not hand-edited: it is kept in sync with §16 of the specification, and any divergence is treated as a defect.
And the mirror rule

A missing provider key does not yield an empty result. It yields CLASSIFIER-NOT-CONFIGURED and an exception. An empty list of violations would mean "checked, nothing found" — a conclusion reached without checking. The system refuses to say it.

Popper's demarcation criterion is not an epigraph here — it is an executable check. This is how it reads in the specification that produced the ssd.py module:

GI_v6_2_COMPLETE.md · Patch 51 (SSD)scientific basis, verbatim
SCIENTIFIC BASIS OF SSD (Popper, 1959): The SSD test is a direct application of Popper's demarcation criterion. An unfalsifiable H1 is not a hypothesis. It is a metaphysical statement. It may be true, but it cannot be tested. In an investigation this means: a conclusion resting on an unfalsifiable H1 = accusation without evidence. RULE [Ban on ad hoc modification] (Popper, 1959): It is forbidden to rescue H1 from an FRCP conflict by adding exceptions that reduce overall falsifiability. Not permitted: "this is an exception because the subject is a special case."
Philosophy compiled into a function. A hypothesis that no conceivable fact could refute is marked unusable, and any conclusion resting on it is capped below a given trust level. Not because that is more honest, but because the prohibition was formulated in 1959, has held up, and now executes automatically.
04 The math kernel

Forty-four operators, held by ten laws

Above the protocols sits a separate layer: a library of 44 strictly formalised mathematical operators across domains — causality (do-operator, back-door adjustment, collider bias, counterfactual), probability (Bayesian update, beta distribution), graphs (centrality, clustering, modularity), information (transfer entropy), vectors, statistics, system dynamics. The model selects them. The model does not execute them.

Ten absolute rules govern that layer. Four of them show the character of the whole system:

docs/MATH-KERNEL-COMPACT-v0_1.mdMATH-KERNEL LAW · 4 of 10
RULE 1 — LLM SELECTS, BACKEND CALCULATES The LLM chooses an OPERATOR ID and forms the call. The LLM does NOT compute the value in latent space. The returned value is a protected fact; the LLM may not modify it. RULE 3 — INCOMPLETE INPUTS → RANGE OR NON LIQUET FORBIDDEN: substituting "average" or "default" values in order to run the formula. RULE 8 — INDEPENDENCE NOT PROVEN → SOURCES COLLAPSE Until independence is proven by provenance graph, sources count as a single cluster. Ten reprinted press releases = one piece of evidence. RULE 10 — FORMULA CONTRADICTION → FRCP If the model predicts Base Risk = LOW while a verified fact signals a crisis: → The fact ALWAYS beats the mathematics. Mathematics cannot overrule a fact.
Rule 10 argues against its own product. A system whose entire purpose is to compute contains an explicit prohibition on trusting its own computation over a verified fact. A beautiful number is not evidence: a separate rule forbids a numeric result, on its own, from ever raising the trust level of a conclusion.
05 The proof

Three times the system caught its own makers

The easiest claim to fake in work like this is "we checked, it's correct." So here are three documented cases where the checking found a defect inside the system itself. Each with a date, a file, and a fix.

Case 1 · invented thresholds · found by spec-versus-code review

The confidence module carried four clean thresholds: HIGH ≥ 0.90, MEDIUM ≥ 0.61, LOW ≥ 0.31, CRITICAL < 0.31. They looked derived. Checked word for word against the specification: not one of them exists in it. The specification divides that scale exactly once — if confidence < 0.30: HITL_REQUIRED. Three surplus thresholds had been invented at some earlier step and were living in the code, shaping verdicts.

Removed. The function now returns exactly the binary split the specification itself uses. Restoring them would violate P0-6, the project's founding rule: no number without a traceable formula. This is precisely the class of error the whole architecture exists to catch — and this time it caught itself.

Case 2 · 44 operators silently inventing inputs · found by a live production run

Local tests were green. The manifest audit was clean. Fifteen demo scenarios against the live endpoint returned fifteen honest 200 OKs. Inside sat the defect: the Bayesian update operator, given only a prior, returned result: 0.8 with status EXECUTED — while the missing likelihood = 0.8 and false_positive_rate = 0.2 were invented by the backend and never shown in the response. All 44 operators behaved this way.

The registry forbids it in as many words: "when priors are unknown, the system must declare NON LIQUET." Fixed; an inputs_used field now exposes every input; invented defaults removed; locked down by 155 tests.

Why local tests never saw it: on a machine without provider keys a mock is substituted, and the invented-number path never ran. The guarantee was held by configuration, not by code. Since then, a live-endpoint run is a mandatory part of every audit after every deploy.

Case 3 · a hallucination inside the checker · live incident, 13 August 2026

The classifier issued a TYPE-2 CRITICAL verdict: "temporal hallucination and factual fabrication: the AI is describing future events (September 2025, December 2025, and August 2026) as if they have already occurred, inventing court decisions that do not exist." Those events lay 8–11 months in the past. The investigative layer had performed flawlessly at the same moment: 25 real sources — forbes.com, techpolicy.press, cato.org.

Cause: the model was never told the current date, and substituted its own training cutoff for "now." That class of error already has a name inside the system — HEURISTIC_SUBSTITUTION, "replacing a hard question with an easy association," after Kahneman. The checker committed the exact error it was built to catch. Fixed by temporal grounding — with an explicit note on what the fix does not do: a claim about 2027 in a 2026 present is still future-dated and must still be flagged.

All three are recorded in the project's own code and documentation with a full account — not in an investor report, but where the next developer will find them. None was found by an outside auditor. The system is built to find these itself.

07 Architecture

How it is put together

A shared core, GI v6.2 — 45 tracked patches (33–71 plus six bridges), 71 modules, 19,003 lines of engine. The core governs how evidence, sources, and conflicting claims live inside an investigation: source status change, arbitration of conflicting facts, cascading trust downgrade, provenance degradation, temporal integrity, investigator fatigue, moral-panic filter, terminal epistemic limit.

Three products stand on it:

  • GOVERNANCE — audits a single piece of AI output: a documented fact, or synthetic persuasiveness in the shape of one.
  • INTELLIGENCE — open-source investigation with live grounded search: source independence, evidence tiers, chains of corroboration.
  • TRACE — the red team: who benefits if this is true, and does the document carry the fingerprints of a thing built to be found.

Plus four named critical combinations — states that are dangerous only in concert: CHAIN DEGRADATION, STRATEGIC DESTRUCTION, PERSONAL LOCK, RESOURCE-TELP. The first fires when provenance, witness chain, and source memory are compromised at once: the trust ceiling is forced down and a human is called, even where no individual signal is critical on its own.

Provider policy

The system calls exactly one model provider — Google Gemini. A direct, repeatedly reaffirmed decision by the author, recorded as irreversible rather than as a configuration detail. An earlier version of the classifier required an Anthropic key the author does not have; that made the entire engine inoperable, and it went unnoticed while the product was not yet wired into the site. The transport was replaced; the system prompt was left untouched.
