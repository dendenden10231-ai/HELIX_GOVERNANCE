## 3. Шаг 1.2 — манифест: предложенная правка портила поставку

### 3.1 Почему «две строки» не годятся

Задание предлагало `rel.as_posix()` плюс `.replace(b'\r\n', b'\n')` для всех
файлов. Первая половина верна, вторая **портит поставку**: PDF, DOCX, ZIP и
TTF нормализацию переводов строк не переживают.

Проверено на реальном файле: `manuscripts/справочники/The Oxford Dictionary Of
Quotations.pdf` начинается с чистого ASCII, NUL-байта в первых килобайтах нет,
поэтому эвристика «двоичный там, где есть NUL» объявила бы его текстом и
пересчитала бы его хэш. Git при этом считает файл двоичным:

```bash
git ls-files --eol | grep -- '-text' | wc -l      # 28
git ls-files --eol -- "manuscripts/справочники/The Oxford Dictionary Of Quotations.pdf"
# i/-text w/-text
```

### 3.2 Из чего на самом деле состоит манифест

Решающий замер, который определил способ починки:

```bash
PYTHONUTF8=1 python - <<'PY'
import hashlib, pathlib, subprocess
def h(b): return hashlib.sha256(b).hexdigest()
raw = pathlib.Path('README.md').read_bytes()
rec = [l for l in pathlib.Path('MANIFEST_SHA256.md').read_text(encoding='utf-8').splitlines()
       if l.endswith('README.md')][0].split()[0]
blob = subprocess.run(['git','cat-file','blob',':README.md'],capture_output=True).stdout
print('CRLF в рабочем дереве:', raw.count(b'\r\n'))
print('raw == записи:', rec == h(raw))
print('lf  == записи:', rec == h(raw.replace(b'\r\n', b'\n')))
print('git blob == записи:', rec == h(blob))
PY
# CRLF в рабочем дереве: 86
# raw == записи: False
# lf  == записи: True
# git blob == записи: True
```

Вывод: манифест описывает **содержимое git-блобов (LF)**, а рабочее дерево на
Windows держит CRLF. Значит каноническая форма — это то, что хранит git, и
спрашивать надо git.

### 3.3 Три машинных бага, а не один

| # | Баг | Следствие на Windows | Как измерено |
|---|---|---|---|
| 1 | `generate()` печатал `str(rel)` | обратные слеши `api\live_hub.py` против прямых в манифесте | `--verify`: 2047 «отсутствуют» + 2048 «лишних» при 2067 записях |
| 1б | `игнорируемое_гитом()` без `-z` | git отдаёт не-ASCII пути в восьмеричных кавычках, сравнение не сходится никогда → игнорируемый кириллический файл молча попадал в поставку | `git ls-files --others --ignored --exclude-standard` против того же с `-z` |
| 2 | хэш считался с сырых байтов | расходятся **2010 хэшей из 2067** | нормализованное сравнение |
| 3 | `sorted(root.rglob("*"))` | `PureWindowsPath` сравнивает без учёта регистра → порядок записей отличается от Linux, регенерация переставляет **~450 строк при неизменных хэшах** | `diff` манифеста до и после: 450 изменённых строк; после правки сортировки — 4 строки (2 файла) |

Третий баг не был заявлен ни в задании, ни в прежнем паспорте — найден при
первой же регенерации.

### 3.4 Как починено

Решение о нормализации берётся у git, а не угадывается:

```bash
git ls-files --eol | awk '{print $1, $2}' | sort | uniq -c | sort -rn
#   2014 i/lf    w/crlf     -> нормализовать CRLF в LF
#     29 i/none  w/none     -> байт в байт
#     28 i/-text w/-text    -> байт в байт (двоичные)
#      1 i/lf    w/lf       -> байт в байт
```

Для файлов, которых git ещё не знает (15 новых), двоичность определяется по
его же правилу — NUL в первых 8000 байтах (`buffer_is_binary`,
`FIRST_FEW_BYTES` в `convert.c`), константа вынесена как `GIT_BINARY_PROBE`.
Пути везде `as_posix()`, игнорируемое запрашивается с `-z`, сортировка по
posix-строке.

### 5.2 Побочная находка: мёртвый дубль маршрута

250 зарегистрированных HTTP-маршрутов против **249** уникальных пар
(путь, метод) — разница и есть дубль. FastAPI печатала при каждой сборке
схемы:

```
UserWarning: Duplicate Operation ID passport_extract_api_ak_passport_extract_post
for function passport_extract at api/router.py
```

Причина: `@router.post("/passport/extract")` был объявлен в `api/router.py`
**дважды** — строки 372 и 1595, обе функции под именем `passport_extract`.
Вторая затирала первую в пространстве имён модуля, но в роутере
регистрировались обе. Starlette матчит по порядку, поэтому запрос всегда ловила
первая, отдававшая `{draft, stats, yaml, manual_fields}`; вторая, отдававшая
только `{yaml, stats}`, **не выполнялась ни разу за всю историю**.

Проверка, что удаление безопасно:

```bash
grep -rn "ak_service.passport_extract" --include="*.py" .
# ./api/router.py:1605:    return ak_service.passport_extract(_NS(text=text))
```

Сервисный метод сохранён — его зовёт `/passport/extract-file`. Удалено только
мёртвое второе объявление.

Поведение проверено живым вызовом, а не рассуждением:

```
POST /api/ak/passport/extract      -> 200
ключи ответа: ['draft', 'manual_fields', 'stats', 'yaml']

stats: ['chapters','characters_found','motifs_found','refrains_found','rhythm_sections']
```

```text
len(old) − len(new) в символах            68      (ровно столько, сколько нашли)
old.replace('\u200b', '') == new          True    (побайтово)
байт: 962 776 → 962 572                   −204    (= 68 × 3 байта UTF-8)
строк / переводов CRLF                    13 887 / 13 887 — без изменений
U+200B: было 68 → стало 0; прочих невидимых (200C, 200D, 2060, FEFF, 2028, 2029) — 0
word-diff: снято 68 токенов, каждый содержит U+200B; добавленные 68 токенов
           равны снятым без U+200B, один в один и в том же порядке
```

Отдельно, чтобы не вводить в заблуждение: «в лоб» сравнение байтов не сходится
(`962 776` против `976 459`), потому что git хранит этот файл с LF, а в рабочем
дереве он с CRLF — то же расхождение, что разобрано в §3.2. С приведением к LF
сходится побайтово, и git при коммите сохранит LF.

**23 passed**, падение ушло. Полный корневой набор после этого — **0 failed**.
