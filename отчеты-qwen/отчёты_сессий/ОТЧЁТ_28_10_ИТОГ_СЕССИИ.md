## 28.10, ночь: красный CI починен по причинам, а не обходом

Воспроизведены все шаги `.github/workflows/102-ci.yml` на этой машине
(`compileall`-эквивалент через `ast.parse(feature_version=(3,11))`, оба набора
pytest, `generate_manifest.py --verify`). Набор HELIX зелёный целиком
(2928 passed). В `tests/` было 9 падений, все одного класса — тесты ждали
русские строки ответов, которые переведены на английский, и пустую ленту
новостей, где теперь честный посев:

| тест | ждал | стало в ответе | правка |
|---|---|---|---|
| test_audit_byok (2 случая) | «символ» | «cannot appear in a key» | маркер переведён |
| test_block9_decision_tree_wired | «не входит» | «not part of the SCN-03 route» | маркер переведён |
| test_судья_не_зовётся_без_спроса | «платный» | «it is paid …» | маркер переведён |
| test_панель_рукописи… | «ВСЕМУ тексту» | «not embedded in the response» | маркер переведён |
| test_newsroom (2 случая) | лента `== []` | посев с пометкой `seed` | проверяется «нет записей без seed» |
| test_newsroom (сбор) | «Вы вошли как» | «You are signed in as» | маркер переведён |

Поведение кода не менялось: правлены только утверждения, которые описывают
текст сообщения, и два ожидания пустого хранилища, где пустота больше не
обещана (посев задокументирован в mr_helix/api/newsroom_seed.py).
После правок: 88 passed в этих пяти файлах, манифест пересобран и сверен
(0 расхождений), коммит 17caf08.

**Про автодеплой.** Триггер сервиса `web` поднимает деплой только когда коммит
трогает боевые пути; коммит из тестов и манифеста деплой не создаёт — это
нормально, прод остался на b0efaa7 со всеми продуктовыми правками. Красный CI
раньше пропускал деплои боевых коммитов (статус SKIPPED у записей 03:40 и
05:26); после этой правки у боевого коммита проверок красных быть не должно.
Лог GitHub Actions с этой машины не читается: репозиторий приватный, `gh` не
установлен, браузер без входа в GitHub отдаёт 404 — поэтому вердикт «зелено»
дан по полному локальному воспроизведению шагов, а не по логу раннера.

## 28.10, поздний вечер: коннектор GitHub → Railway восстановлен

У сервиса `web` проекта `delightful-radiance` не оказалось ни одного
репозиторного триггера (`service.repoTriggers` = пусто), поэтому пуши в `main`
не создавали деплоев вообще — ни успешных, ни пропущенных; последние деплои
дня были ручными redeploy. Триггер создан через `deploymentTriggerCreate`:
репозиторий `dendenden10231-ai/102`, ветка `main`, окружение `production`,
`checkSuites: true` (красные проверки GitHub по-прежнему останавливают деплой —
это защита, а не помеха). Проверка в бою — коммит с этим абзацем: он пушится
сразу после создания триггера, и Railway обязан либо начать сборку (CI зелёный),
либо показать SKIPPED (CI красный).
