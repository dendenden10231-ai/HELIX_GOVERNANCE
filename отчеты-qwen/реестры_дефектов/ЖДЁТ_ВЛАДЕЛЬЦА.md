## 🔴 1. Разобраться, почему не исполняются СВОИ workflow

**Здесь я раньше говорил неточно, поправка.** «Actions выключены» —
неверно. Проверено 06.09:

| workflow | чей | последний запуск |
|---|---|---|
| Dependency Graph (dependabot) | GitHub | **сегодня 16:55, success** |
| Copilot Code Review | GitHub | 18.08, success |
| **AK-MASTER CI** (`ak-master-ci.yml`) | наш | **11 июля**, хотя объявлен на `[push, pull_request]` |
| **Проверка живого сайта** (`site-health.yml`) | наш | два запуска, оба **висят `queued`** и не стартовали никогда |

Все четыре в состоянии `active`. То есть **свои** workflow не исполняются,
а служебные GitHub-овские — исполняются. Сегодня в 16:55 в `main` ушёл
push (слияние), dependabot на этом же коммите отработал, а `AK-MASTER CI`
не запустился вовсе.

`queued` без старта означает, что задание принято и ждёт раннера. На
приватном репозитории это чаще всего **исчерпанные минуты Actions или
лимит трат**, а не выключенный тумблер.

Смотреть здесь:

```
github.com/settings/billing            → Actions minutes: сколько осталось
github.com/dendenden10231-ai/101/settings/actions
                                       → Actions permissions, Workflow permissions
```

**Цена простоя.** Пока это не решено, любое моё «зелено» — локальный
прогон (4952 теста), а не CI. Проверить мою работу независимо от меня
нечем, и это ровно то, на что вы жаловались с самого начала.
