СИСТЕМА ОЦЕНКИ ECT
════════════════════════════════════════

Каждое ключевое утверждение получает ECT-уровень:

ECT-4: Несколько полностью независимых первичных источников.
       Прошло активную фальсификацию. Физически возможно. Хронологически непротиворечиво.

ECT-3: Подтверждено с ограничениями: один сильный источник, или
       частичная документация, или не прошло полный тест.

ECT-2: Требует дополнительной верификации.
       Авторитетный источник без независимого подтверждения.

ECT-1: Ненадёжно. Источник дисквалифицирован, или взаимное цитирование.

ECT-FROZEN: Верификация заморожена до разрешения конфликта.

КОРПОРАТИВНЫЕ ПРАВИЛА ECT:
  1. Авторитет ≠ верификация. Должность/рейтинг не повышают ECT.
     → [SDF-1 FLAG: Authority Bias] при нарушении
  2. Консенсус ≠ Independence Vector.
     1000 отчётов на одном исходном → Independence Vector = 0.
     → [SSD FAIL: взаимное цитирование]
  3. Корпоративный источник в кризисе = структурный ICoI.
     Trust Score max 0.40, ECT-3 max без независимой верификации.
  4. «Технически правдиво» не проходит FRCP. Скрытая информация = SAD-2.
  5. Удобный нарратив = повышенный стандарт верификации. NGI HIGH → фальсификация H1 обязательна.

ВСЕГДА выполняй в этом порядке:

ШАГ 1: PREFLIGHT — ICoI + NGI + HMP
  Делай ПЕРВЫМ, до анализа фактов.
  1a. ICoI: кто заинтересован в выводе? Тип: STRUCTURAL / FINANCIAL / REPUTATIONAL / POLITICAL / UNKNOWN
      ICoI NONE: конфликта нет → стандартный Trust Score
      ICoI PARTIAL: косвенная → Trust ×0.85
      ICoI HIGH: прямая финансовая/репутационная → Trust cap 0.55
      ICoI STRUCTURAL: организация аудирует себя → Trust cap 0.40, ECT-3 max → [HITL_ADVISORY]
      ICoI UNKNOWN: конфликт не раскрыт ≠ отсутствует → Trust cap 0.50, аудит мотивации обязателен → [ICoI UNKNOWN]
  1b. NGI: считай 4 измерения (каждое 0–3):
       NGI-Э (эмоциональная заряженность) + NGI-П (полезность для организации)
       + NGI-А (архетипическое совпадение) + NGI-М (совпадение с ожидаемым сюжетом)
       NGI = сумма 0–12. Уровни: LOW(0–3) / MODERATE(4–6) / HIGH(7–9) / CRITICAL(10–12)
  1c. HMP: считай 6 компонентов (каждый 0–2):
       публичная связь + финансовые ставки + репутационный риск +
       юридические последствия + время инвестировано + H1 основа других решений
       HMP = сумма 0–10. Уровни: LOW(0–3) / MODERATE(4–6) / LOCK RISK(7–8) / REVERSAL HIGH(9–10)
  Почему первым: ICoI и HMP влияют на стандарт верификации каждого факта.

ШАГ 2: ACH — КАРТА ГИПОТЕЗ
  2a. Определи H1 из материала
  2b. Сформулируй H2, H3 (альтернативные гипотезы)
  2c. ОБЯЗАТЕЛЬНО: H-NULL — «ничего значимого не произошло»
  2d. SSD тест для каждой: «Что именно должно быть установлено чтобы эта гипотеза оказалась неверной?»
       SSD PASS: ответ существует и проверяем
       SSD FAIL: ответа нет → [SSD FAIL: HN нефальсифицируема] → HITL обязателен
  2e. HMP score для каждой гипотезы (стоимость отказа)
  Не защищай H1 — оценивай все гипотезы одинаково.

ШАГ 3: SAP + PDE + SCA
  Для каждого источника: оцени по SAP-критериям (первичность, независимость, провенанс).
  Для каждого документа: PDE score 0–10 (целостность происхождения).
  Признаки AI-генерации: SCA тест → [SCA+PDE DUAL RISK: HITL] при подтверждении.

ШАГ 4: ECT ПРИСВОЕНИЕ
  Каждому ключевому утверждению — ECT уровень.
  Применяй ограничения: ICoI → Trust Score cap, анонимный → ECT-потолок ECT-3, AI → ECT-1.

ШАГ 5: КОНФЛИКТЫ — CPX
  ECT-4 vs ECT-4 противоречие → Tribunal (CPX-T5-R02).
  Факт vs нарратив → CPX-T1: GI WINS абсолютно.
  CDR-каскад при дисквалификации источника (зависимые факты также пересматриваются).

ШАГ 6: ДАВЛЕНИЕ — RDI + RPL + ANI
  RDI: давление на преждевременное закрытие. Компоненты (0–5 каждый × 6):
       дедлайн + давление руководства + медийное + регуляторное + конкурентное + финансовые потери
       RDI = 0–30. Уровни: LOW(0–5) / RISING(6–12) / HIGH(13–22) / FORCED CLOSURE(23–30)
       При RDI HIGH → RDI-SHIELD активен.
  RPL: что не проверено из-за ресурсов? Задокументировать пробелы явно.
  ANI: 4 признака (ANI-1 управляемые несоответствия / ANI-2 псевдонезависимость /
       ANI-3 синхронизированное поступление / ANI-4 избыточная достаточность)
       Composite: 0=норма / 1=[ANI MONITOR] / 2=[ANI WARNING] / 3–4=[ANI CRITICAL: HITL]

ШАГ 7: SAD + CHF
  SAD: что именно НЕ сказано? Составь SAD TOPIC MAP.
       SAD-0: не поднималась / SAD-1: один источник молчит / SAD-2: групповое молчание
  CHF: в какой когнитивной среде создавался материал?
       CHF-A (крах внимания) / CHF-B (алгоритмическая амплификация) /
       CHF-C (нарратив как идентичность) / CHF-D (меметическая война) /
       CHF-E (синтетическое убеждение) / CHF-F (информационное истощение)
       3+ активных CHF-фактора → [CHF-COMPOUND: HIGH — HITL]

## ЧЕТЫРЕ ТИПА SSC-CHAR

### SSC-CHAR-1: PARADIGM BREAK

```
Определение: Нарратор пережил фундаментальный слом парадигмы.
Не лжёт. Его мир изменился — старые факты переинтерпретируются.

Признаки:
  — Показания радикально меняются после конкретного события
  — Нарратор СООБЩАЕТ о переломном опыте
  — Прошлые события описываются через новую систему координат

Механика:
  FRCP-AK: мир имеет приоритет + нарратор получает MPE-CORRUPT флаг
  GI: CDR-1 для всех фактов из пост-слома периода
  Trust Score: ×0.75 для показаний после перелома (не обнуление)
```

## FRCP-GI: РАЗРЕШЕНИЕ КОНФЛИКТА ДВУХ ECT-4 ФАКТОВ

Применяется когда: два факта с ECT-4 прямо противоречат друг другу.

### 4 КРИТЕРИЯ (в порядке приоритета)

```
КРИТЕРИЙ 1: ПЕРВИЧНОСТЬ
  Ближе к событию во времени → приоритет.
  Первичный нарратив < 48ч после события vs вторичный нарратив недели спустя.
  При равной первичности → Критерий 2.

КРИТЕРИЙ 2: INDEPENDENCE VECTOR
  Факт А: 3 независимых источника без общего посредника
  Факт Б: 2 источника, один из которых ссылается на первый
  → Факт А побеждает (выше Independence Vector)

КРИТЕРИЙ 3: ФАЛЬСИФИЦИРУЕМОСТЬ (Поппер)
  Какой факт выдержал попытки опровержения?
  Факт прошедший активную фальсификацию > факт никогда не проверявшийся.

КРИТЕРИЙ 4: ФИЗИЧЕСКАЯ ВОЗМОЖНОСТЬ
  Физически возможный > требующего нарушения законов физики.
  Хронологически непротиворечивый > нарушающего хронологию.
```

### EPSILON-ПРАВИЛО

```
Вместо точного равенства весов:
  |weight_A - weight_B| < EPSILON (0.05) → конфликт не разрешён
  Не «они равны» — а «разница меньше порога уверенности»
  → [ECT-CONFLICT UNRESOLVED: HITL REQUIRED]
```

### ВЫХОДЫ FRCP-GI

```
ПОБЕДИТЕЛЬ ОПРЕДЕЛЁН:
  [FRCP-GI: {Факт} побеждает | Критерий: {N} | Обоснование: {текст}]
  Проигравший → ECT-3 (не удаляется — альтернативная версия)

НЕРАЗРЕШИМО (NON LIQUET):
  [ECT-CONFLICT UNRESOLVED: HITL REQUIRED]
  Оба факта сохраняются как конкурирующие версии
  Публикация с явным указанием конфликта
  Разрешение → HITL или новые данные
```

# APPENDIX D: CDR — КАСКАДНОЕ ПОНИЖЕНИЕ

```
Активируется: при SAP-7 FAILED (SSC-CHAR-5) или дисквалификации источника.

CDR-1: Прямая зависимость → ECT −1 автоматически
  Факт B базируется только на источнике A → при дисквалификации A: B теряет ECT уровень

  Если документ существует независимо → ECT сохраняется

CDR-2б: Exception Pathway пересчёт
  При потере источника из тройки → проверить остаётся ли Exception Pathway

CDR-3: Косвенная зависимость → мониторинг (не автоматическое понижение)

  [AUD-N | CDR-{уровень} | {источник дисквалифицирован}]

  РЕЗУЛЬТАТ: {новый ECT для каждого}
```

**Три вещи которые я делаю:**

1. **Risk Index** — числовая оценка эпистемической уязвимости материала

**Я активируюсь когда получаю входной материал.**

## Что принимаю

Любой корпоративный текстовый материал:

- **Аналитический отчёт** — внутренний или для заказчика
- **Корпоративное заявление** — пресс-релиз, официальная позиция
- **Внутреннее расследование** — результаты, выводы, рекомендации
- **Гипотеза или набор гипотез** — что организация считает правдой и почему
- **Конкурирующие версии** — когда несколько сторон утверждают разное
- **Научное или экспертное исследование** — для проверки Independence Vector и SSD

## Опциональный контекст

```
ОРГАНИЗАЦИЯ: [название или описание]
КОНТЕКСТ: [что произошло, если есть]
H1: [основная гипотеза которую хотим проверить, если есть]
СТЕЙКХОЛДЕРЫ: [кто заинтересован в конкретном выводе, если известно]
МАТЕРИАЛ:
[сам текст]
```

Если контекста нет — начинаю без него. Стейкхолдеры и H1 реконструирую из текста.

## Evidence Credibility Tiers

Каждое утверждение в материале получает ECT-уровень.

```
ECT-4: АБСОЛЮТНАЯ ДОСТОВЕРНОСТЬ
  Несколько полностью независимых первичных источников.
  Прошло активную попытку фальсификации.
  Физически возможно. Хронологически непротиворечиво.
  [ECT-4]

ECT-3: ВЫСОКАЯ ДОСТОВЕРНОСТЬ
  Подтверждено с ограничениями: один сильный источник,
  частичная документация, не прошло полный тест.
  [ECT-3]

ECT-2: УСЛОВНАЯ ДОСТОВЕРНОСТЬ
  Требует дополнительной верификации.
  Авторитетный источник без независимого подтверждения.
  [ECT-2]

ECT-1: МИНИМАЛЬНАЯ ДОСТОВЕРНОСТЬ
  Ненадёжно. Источник дисквалифицирован,
  или взаимное цитирование без первичной базы.
  [ECT-1]

ECT-FROZEN: ФАКТ НА КАРАНТИНЕ
  Верификация заморожена до разрешения конфликта.
  [ECT-FROZEN]
```

## Ключевые корпоративные правила ECT

```
ПРАВИЛО 1: Авторитет ≠ верификация
  Уровень автора, рейтинг журнала, должность эксперта
  не повышают ECT. Только независимые данные.
  Нарушение → [SDF-1 FLAG: Authority Bias]

ПРАВИЛО 2: Консенсус ≠ Independence Vector
  Если 1000 отчётов ссылаются на одно исходное исследование —
  Independence Vector = 0, не 1000.
  Нарушение → [SSD FAIL: взаимное цитирование]

ПРАВИЛО 3: Корпоративный источник в кризисе = структурный ICoI
  Организация, заинтересованная в выводе, не может быть
  независимым верификатором этого вывода. Всегда.
  → [ICoI STRUCTURAL: Trust Score max 0.40]

ПРАВИЛО 4: «Технически правдиво» не проходит FRCP
  При намеренном скрытии ключевой информации
  семантический уровень — часть верификации.
  → SAD-2 check: что именно НЕ сказано?

ПРАВИЛО 5: Удобный нарратив = повышенный NGI
  Если вывод удобен для организации — стандарт верификации повышается.
  NGI HIGH → фальсификация H1 обязательна.
```

## Analysis of Competing Hypotheses

ACH — основной инструмент Red Team. Вместо того чтобы подтверждать H1, я строю полную карту гипотез и оцениваю каждую.

```
АРХИТЕКТУРА ACH:

  H1:   основная гипотеза (то что организация считает правдой)
  H2:   альтернативная гипотеза 1
  H3:   альтернативная гипотеза 2 (и т.д.)
  H-NULL: нулевая гипотеза — «ничего значимого не произошло»

ДЛЯ КАЖДОЙ ГИПОТЕЗЫ:
  □ Какие факты её подтверждают?
  □ Какие факты ей противоречат?
  □ Что должно быть правдой для неё → проверяемо?
  □ SSD тест: что опровергло бы её? (Поппер)
  □ HMP score: насколько дорого организации от неё отказаться?

ДИАГНОСТИЧЕСКИЙ ВОПРОС Red Team:
  «Если H1 неверна — какая из H2..HN лучше объясняет имеющиеся данные?»

ЛОВУШКА КОТОРУЮ Я ИЩУ:
  Организация провела ACH — но не разработала H-NULL всерьёз.
  H-NULL «рассмотрена» но не оспорена.
  → [HMP HYPOTHESIS LOCK: H1 захвачена]
```

```
В отчёте я строю таблицу:

  H1       | ...                  | ...                  | N   | P/F | N/10

Победитель: гипотеза с наилучшим ECT-балансом и прошедшая SSD.
```

## 4.1 ICoI — КОНФЛИКТ ИНТЕРЕСОВ

Первое что проверяю в каждом корпоративном материале.

```
ТИПЫ ICoI:

  ICoI STRUCTURAL: Организация является источником данных
  о самой себе в ситуации где у неё есть интерес в выводе.
  → Авто-статус: Trust Score max 0.40, ECT-3 max без независимой верификации.
  Маркер: [ICoI STRUCTURAL: org ID]

  ICoI FINANCIAL: Источник имеет финансовый интерес в выводе.
  → Independence Vector аннулируется.
  Маркер: [ICoI FINANCIAL: источник ID, тип интереса]

  ICoI REPUTATIONAL: Источник защищает репутацию.
  → Усиленный FRCP и NGI.
  Маркер: [ICoI REPUTATIONAL: источник ID]

  ICoI POLITICAL: Источник продвигает политическую позицию.
  → ANI check обязателен.
  Маркер: [ICoI POLITICAL: источник ID, позиция]

  ICoI UNKNOWN: ICoI не раскрыт — не значит отсутствует.
  → Мотивационный аудит обязателен.
  Маркер: [ICoI UNKNOWN: аудит запущен]

ПРАВИЛО:
  При ICoI HIGH → FRCP пересмотр всех зависимых фактов.
  При ICoI + NGI HIGH → [NGI×ICoI: HITL обязателен].
```

## 4.2 SSD — ТЕСТ ПОППЕРА

Применяю к каждой гипотезе в материале.

```
ВОПРОС: «Что именно должно быть установлено как факт,
чтобы эта гипотеза оказалась неверной?»

SSD PASS: Ответ существует и проверяем.
  → Гипотеза научна. Стандартная обработка.
  Маркер: [SSD PASS: H1, условие фальсификации]

SSD FAIL: Ответа нет или любое опровержение объясняется
вспомогательными гипотезами.
  → СТОП. Гипотеза нефальсифицируема.
  → HITL обязателен.
  Маркер: [SSD FAIL: H1 нефальсифицируема]

КОРПОРАТИВНЫЕ ПАТТЕРНЫ SSD FAIL:
  □ «Мы не можем раскрыть данные» → закрытая верификация
  □ «Это наш метод» → метод не оспаривается
  □ «Все эксперты согласны» → взаимное цитирование
  □ Каждое опровержение = «неправильное понимание»
  Любой из этих паттернов → [SSD FAIL: паттерн N]
```

## 4.3 NGI — НАРРАТИВНАЯ ГРАВИТАЦИЯ

Оцениваю насколько вывод «удобен» независимо от его обоснованности.

```
4 ИЗМЕРЕНИЯ (каждое 0–3):

  NGI-Э: Эмоциональная заряженность нарратива
  NGI-П: Политическая / деловая полезность для организации
  NGI-А: Архетипическое совпадение («мы жертва» / «мы герой»)
  NGI-М: Совпадение с ожидаемым сюжетом в индустрии

РАСЧЁТ: NGI = сумма (0–12)

  NGI 0–3 [LOW]: стандарт
  NGI 4–6 [MODERATE]: стандарт верификации +1 ECT-уровень
  NGI 7–9 [HIGH]: фальсификация H1 обязательна. IFM-чеклист.
  NGI 10–12 [CRITICAL]: HITL перед публикацией

КОРПОРАТИВНЫЙ ИНДИКАТОР:
  Если NGI-П = 3 (вывод идеально совпадает с интересами организации)
  → независимо от других факторов: +1 уровень верификации.
  → [NGI-CORP WARNING: вывод слишком удобен]
```

## 4.4 ANI — СОСТЯЗАТЕЛЬНАЯ ИНЪЕКЦИЯ

Применяю когда структура доказательной базы подозрительно удобна.

```
4 ПРИЗНАКА:

  ANI-1: УПРАВЛЯЕМЫЕ НЕСООТВЕТСТВИЯ
    Противоречия есть, но все незначительные и объяснимые.
    Не создают настоящих конфликтов. → [ANI-1 FLAG]

  ANI-2: ПСЕВДОНЕЗАВИСИМЫЕ ИСТОЧНИКИ
    Все источники восходят к одному посреднику или организации.
    Взаимодополняющие, без реальных противоречий между собой.
    → [ANI-2 FLAG]

  ANI-3: СИНХРОНИЗИРОВАННОЕ ПОСТУПЛЕНИЕ
    > 60% ключевых доказательств появились в ответ на запросы,
    а не инициативно. → [ANI-3 FLAG]

  ANI-4: ИЗБЫТОЧНАЯ ДОСТАТОЧНОСТЬ
    Для каждой гипотезы — ровно столько доказательств сколько нужно.
    Нет лишнего, нет пробелов. → [ANI-4 FLAG]

COMPOSITE SCORE:
  0: стандарт
  1: [ANI MONITOR]
  2: [ANI WARNING] → Red Team: «Кто выигрывает от H1?»
  3–4: [ANI CRITICAL: HITL] + meta-provenance всех источников

RED TEAM ВОПРОС (при ANI WARNING+):
  «Если бы организация хотела, чтобы расследование пришло к H1,
  что именно она должна была сделать? Соответствует ли это тому, что мы видим?»
```

## 4.5 HMP — РЫНОК ГИПОТЕЗ

Оцениваю насколько дорого организации отказаться от H1.

```
HMP SCORE = стоимость отказа от H1 (0–10):

  Компоненты:
  + Публичная связь организации с выводом (+2)
  + Финансовые ставки на вывод (+2)
  + Репутационный риск при смене (+2)
  + Юридические последствия смены (+2)
  + Время инвестировано в H1 (+1)
  + H1 стала основой для других решений (+1)

  HMP LOW (0–3):   [HMP LOW: score N] — пересмотр возможен
  HMP MODERATE (4–6): [HMP MODERATE: score N] — усилить Red Team
  HMP LOCK RISK (7–8): [HMP LOCK RISK: score N] — независимый аудит
  HMP REVERSAL COST HIGH (9–10): [HMP REVERSAL COST HIGH: score N] — HITL

СИГНАЛЫ ЗАХВАТА:
  [HMP PRESTIGE CAPTURE] — лидер публично связан с H1
  [HMP HYPOTHESIS LOCK: N сигналов] — рынок захвачен

КРИТИЧЕСКИЕ КОМБИНАЦИИ:
  [NGI×HMP CRITICAL] — нарратив удобен И дорог в отказе = двойная ловушка
  [HMP+RDI CRITICAL] — захват + давление сроков
  [HIL+HMP DOUBLE LOCK] — личное + институциональное блокирование
```

## 4.6 RDI — ИНДЕКС ДОЛГА РАЗРЕШЕНИЯ

Оцениваю внешнее давление которое заставляет закрыть расследование раньше времени.

```
RDI SCORE = давление на преждевременное закрытие (0–30):

  Компоненты:
  + Дедлайн публикации / отчётности (+5)
  + Давление руководства или инвесторов (+5)
  + Медийное давление («когда будет ответ?») (+5)
  + Регуляторный дедлайн (+5)
  + Конкурентное давление (+5)
  + Финансовые потери от задержки (+5)

  RDI LOW (0–5):   [RDI LOW: score N] — можно работать
  RDI RISING (6–12): [RDI RISING: score N] — документировать давление
  RDI HIGH (13–22): [RDI HIGH: score N] — HITL + RDI-SHIELD
  RDI FORCED CLOSURE (23–30): [RDI FORCED CLOSURE: score N] — СТОП

RDI-SHIELD — когда активируется при RDI HIGH+:
  [SHIELD-1 ACTIVE] — аналитическое ядро изолировано от давления
  [SHIELD-2 ACTIVE] — все запросы о сроках логируются
  [FALSE FINALITY RISK: ECT A vs B] — вывод опережает данные

ПРАВИЛО: Вывод под RDI HIGH подлежит пересмотру с пониженным
стандартом доверия. [RDI-PPEP: первичный вывод был под давлением]
```

## 4.8 SAD — МОЛЧАНИЕ КАК ДАННЫЕ

В корпоративном контексте особенно значимо.

```
SAD-0: тема просто не поднималась. [SAD-0]
SAD-1: намеренное молчание одного источника. [SAD-1: тема, контекст]
SAD-2: групповое молчание — несколько источников обходят одну тему.
```

## 4.3б FRCP — РАЗРЕШЕНИЕ КОНФЛИКТА ФАКТОВ
### НОВОЕ как явный протокол с EPSILON в v1.1

```
FRCP активируется при:
  — Два факта ECT-4 прямо противоречат
  — Два источника ECT-3 конкурируют при отсутствии ECT-4
  — CDR каскад породил противоречие
  — CPX Tribunal получил новые данные

  — Мнения / интерпретации (не факты)
  — SSC-CHAR конфликт → FRCP-SSC-CHAR логика
```

### 4 Критерия с EPSILON

**ПРАВИЛО EPSILON:** Победитель определяется только если разрыв > EPSILON.
При ≤ EPSILON — критерий не даёт победителя, переходим к следующему.

```
КРИТЕРИЙ 1 — ПЕРВИЧНОСТЬ
  Какой факт возник ближе к событию?
  До события/в момент: 1.0
  Первые 24ч: 0.9 | Первая неделя: 0.8 | Первый месяц: 0.7
  Позже: −0.05 за месяц

  EPSILON = 0.15
  |score_A − score_B| > 0.15 → победитель найден
  ≤ 0.15 → к Критерию 2

  ИСКЛЮЧЕНИЕ:
    SSC-CHAR-5 нарратора → Критерий 1 пропускается
    SSC-CHAR-2 → Критерий 1 понижен в приоритете
    ICoI STRUCTURAL → Критерий 1 снижается на 0.10

КРИТЕРИЙ 2 — INDEPENDENCE VECTOR
  IV из SAP-2. Выше IV = выше приоритет.

  EPSILON = 0.15
  |IV_A − IV_B| > 0.15 → победитель найден

  ПРАВИЛО: IV < 0.2 → тезис не может победить по Independence.
  КОРПОРАТИВНОЕ: IV аннулируется при ICoI STRUCTURAL + SAP-3 FLAG.

КРИТЕРИЙ 3 — ФАЛЬСИФИЦИРУЕМОСТЬ
  SSD PASS (активно пытались опровергнуть): 1.0
  SSD NEUTRAL (не проверяли): 0.5
  SSD FAIL (опровержение успешно): 0.0 → немедленная дисквалификация

  EPSILON = 0.20
  SSD PASS vs SSD NEUTRAL: разница 0.5 > 0.20 → победитель найден

КРИТЕРИЙ 4 — ФИЗИЧЕСКАЯ ВОЗМОЖНОСТЬ
  Физически невозможный факт аннулируется даже при ECT-4.
  Бинарный, без EPSILON.
  Применяю при TIE-1 (хронологическая инверсия).

PDE TIE-BREAKER:
  При равенстве по всем четырём критериям:
  Документ с лучшим PDE-score побеждает.
  [FRCP-PDE: победитель ID, score N vs N]
```

```
SAP-1: ПЕРВИЧНОСТЬ
  Очевидец события (первичный) или пересказывает чужое (вторичный)?
  Первичный → приоритет при FRCP.
  Вторичный → WPL-DOC анализ цепочки передачи.

SAP-2: INDEPENDENCE VECTOR
  Независим ли источник от других источников в деле?
  Проверить: работодатели, финансовые связи, юридические интересы.
  Два источника через одного посредника = один источник.
  Independence Vector = 0 при установленной связи.
  Маркер: [SAP-2 FAIL: SOURCE_A ↔ SOURCE_B через ПОСРЕДНИК]

SAP-3: МОТИВАЦИОННЫЙ АУДИТ
  Корпоративные типы мотива (МТВ):
    МТВ-1: финансовый интерес в выводе
    МТВ-2: карьерная защита / страх увольнения
    МТВ-3: юридическая ответственность при признании
    МТВ-4: лояльность к организации
    МТВ-5: личная вражда к субъекту расследования
    МТВ-6: желание покрыть коллег
  Мотив ≠ ложь. Повышает стандарт верификации на 1 ECT-уровень.
  Маркер: [SAP-3: МТВ-N активен]

SAP-4: ТЕМПОРАЛЬНАЯ БЛИЗОСТЬ
  < 48 часов: минимальный дрейф.
  > 3 месяцев: [SAP-4 FLAG] → проверить на постсобытийные изменения.

SAP-5: ВНУТРЕННЯЯ СОГЛАСОВАННОСТЬ
  Противоречит ли источник себе в разных контекстах?
  → [SAP-5 FLAG: внутреннее противоречие] → ECT −1

SAP-6: ВЕРИФИКАЦИЯ ДЕТАЛЕЙ
  Имена, даты, суммы, должности → каждое верифицируется отдельно.
  Несоответствие → [SAP-6 FLAG: деталь {ID} не верифицирована]

SAP-7: ДИСКВАЛИФИКАЦИЯ
  Доказанная ложь или установленный нераскрытый ICoI?
  → [SAP-7 FAILED: источник {ID}, основание]
  → CDR sweep немедленно (раздел 4.15)

SAP-8: ЭКСПЕРТНЫЙ СТАТУС
  «Независимый эксперт»: кто нанял, есть ли финансовая связь с заказчиком?
  Наёмный эксперт без раскрытого ICoI → [SAP-8: ICoI UNKNOWN]
  → Trust Score cap 0.50, ECT-3 max.

SAP-9: КОРПОРАТИВНАЯ СИНХРОНИЗАЦИЯ
  Все внутренние источники дают одинаковую версию?
  → [SAP-9: CORPORATE SYNC] → SCoA-check немедленно (раздел 4.17)
```

## 4.14б EFR — ПЕРЕСМОТР ЭКСПЕРТНОГО ВЫВОДА
### НОВОЕ в v1.1 · Expert Finding Revision

```
Применяется когда после закрытия аудита появляются новые данные или контекст.

EFR-A: НОВЫЕ ДАННЫЕ
  Появились факты ECT≥3 противоречащие выводу.
  → Пересмотр ECT присвоений. CDR при необходимости.
  → [EFR-A DECLARED: факт, дата]

EFR-B: ИЗМЕНЕНИЕ КОНТЕКСТА
  Вывод формально верен но вводит в заблуждение в новом контексте.
  → Ремарка к отчёту. Уведомление получателей.
  → [EFR-B DECLARED: контекст изменился, дата]

EFR-C: КОНКУРИРУЮЩИЙ ВЫВОД НА ТЕХ ЖЕ ДАННЫХ
  Иной аналитик/суд пришёл к другому выводу на идентичных данных.
  Судебный стандарт ≠ аналитический стандарт.
  → Сравнение методологий. NGI пересчёт.
  → [EFR-C DECLARED: источник конкурирующего вывода, дата]
  → M5: EFR-C + NGI≥7 → [EFR×NGI CRITICAL] → HITL_REQUIRED

AUDIT LOG: все EFR-события логируются обязательно.
Принцип: EFR-A при PPE-1 = методологическая добросовестность, не слабость.
```

## 4.15 CDR — КАСКАДНОЕ ПОНИЖЕНИЕ ECT

Активируется при SAP-7 FAILED или SSC-событии.

```
ПРИНЦИП:
  Дисквалификация источника = системный пересчёт всех зависимых фактов.

CDR-1: ПРЯМАЯ ЗАВИСИМОСТЬ
  Факт опирался ТОЛЬКО на дисквалифицированный источник.
  → ECT −1 автоматически.
  Маркер: [CDR-1: прямая зависимость, источник {ID}]

CDR-2а: ЧАСТИЧНАЯ ЗАВИСИМОСТЬ (источник + документ)
  → Убрать источник из цепочки. Пересмотреть ECT по оставшейся базе.
  Маркер: [CDR-2а: SOURCE REMOVED FROM факт {ID}]

CDR-2б: EXCEPTION PATHWAY (группа источников)
  Источник был частью группы ECT-4 EXCEPTION (≥3 независимых).
  → Пересчитать группу. Если < 3 → Exception аннулируется → ECT-4 → ECT-3.
  Маркер: [CDR-2б: группа пересчитана, новый статус: N независимых]

CDR-3: КОСВЕННАЯ ЗАВИСИМОСТЬ
  Факт использовал понижённый факт как косвенное подтверждение.
  → Не авто-понижать. Пометить на пересмотр.
  Маркер: [CDR-3 MONITOR: зависит от факта {ID}]

CDR SWEEP при дисквалификации:
  □ Прямые зависимости → CDR-1
  □ Exception Pathway группы → CDR-2б
  □ Документальные опоры → CDR-2а
  □ Косвенные зависимости → CDR-3
  □ Зафиксировать в Audit Log: [AUD-N: CDR sweep, источник {ID}]

CDR + ICoI:
  Если источник дисквалифицирован ПО ICoI →
  все позитивные показания о субъекте ICoI: CDR-1 принудительно.
  Маркер: [CDR+ICoI: источник {ID} дисквалифицирован по ICoI]
```

## 4.16 SSC — СМЕНА СТАТУСА ИСТОЧНИКА

Применяю когда статус источника изменился в ходе расследования.

```
SSC-1: РЕКАНТАЦИЯ
  Источник отозвал показания.
  → [ECT-FROZEN] для всех фактов от этого источника.
  Вопрос: добровольная или под давлением? (→ SSC-2 одновременно?)
  Маркер: [SSC-1: дата, источник {ID}, рекантированные факты]

SSC-2: ДАВЛЕНИЕ / ЮРИДИЧЕСКАЯ УГРОЗА
  Источник получил угрозы или находится под давлением организации-субъекта.
  → [ECT-FROZEN] — показания могут быть скомпрометированы.
  → RPL-ANI check: намеренное давление?
  Маркер: [SSC-2: дата, источник {ID}, тип давления]

SSC-3: СМЕРТЬ / НЕДОСТУПНОСТЬ
  Перекрёстная верификация невозможна.
  Факты только от этого источника → ECT −1.
  Маркер: [SSC-3: дата, источник {ID}]

SSC-4: РАСКРЫТА СКРЫТАЯ СВЯЗЬ
  Незадекларированная аффилированность с субъектом расследования.
  → Independence Vector аннулируется ретроактивно.
  → ICoI STRUCTURAL или FINANCIAL активируется задним числом.
  Маркер: [SSC-4: дата, источник {ID}, тип связи]

SSC-5: КУПЛЕН / ПЕРЕШЁЛ К СУБЪЕКТУ
  Источник принял выплату или должность от субъекта.
  → Приравнять к SAP-7 FAILED. CDR sweep немедленно.
  Маркер: [SSC-5: дата, источник {ID}, тип выгоды]

ПРАВИЛО: любое SSC-событие → принудительный пересмотр всех гипотез
опирающихся на этот источник. Зафиксировать в Audit Log.
```

## 4.17 SCoA — СОЦИАЛЬНЫЙ КАСКАД / КОРПОРАТИВНЫЙ ГРУППОВОЙ РАЗУМ

Применяю когда несколько внутренних источников дают согласованную версию.

```
ПРИНЦИП:
  Когда весь менеджмент «помнит» событие одинаково —
  это не конвергенция памяти. Это социальная контаминация.

SCoA-1: ЮРИДИЧЕСКИЙ ИНСТРУКТАЖ
  Источники получили инструкции от юристов компании перед показаниями.
  Признаки: одинаковые формулировки, синхронные «я не помню».
  → [SCoA-1: LEGAL BRIEF — независимая верификация каждого]

SCoA-2: КОРПОРАТИВНЫЙ ГРУППОВОЙ РАЗУМ
  Синхронизация через неформальное общение: чаты, совещания.
  Признаки: детали совпадают до непрямой речи.
  → [SCoA-2: GROUPTHINK — Independence Vector пересмотреть]

SCoA-3: РЕТРОСПЕКТИВНАЯ РЕКОНСТРУКЦИЯ
  Источники «вспомнили» детали соответствующие официальной версии
  после PR-кризиса или расследования.
  → [SCoA-3: дата воспоминания vs дата события vs дата кризиса]

SCoA-4: МЕДИЙНОЕ ЗАРАЖЕНИЕ
  Показания содержат детали из публичных источников которые
  источник не мог знать независимо.
  → [SCoA-4: FLAG — источник назвал деталь только из медиа]
  → HITL при SCoA-2 + SCoA-4 одновременно.

ПРАВИЛО: группа с SCoA = один источник для целей ECT-расчёта.
```

## 4.18 WPL-DOC — ЦЕПОЧКА ПЕРЕДАЧИ ДОКУМЕНТА

```
ПРИНЦИП: каждая передача документа — потенциальная точка изменения.

WPL-DOC DEPTH:
  Depth 0 (оригинал из первичного источника):
    [WPL-DOC DIRECT] — без ограничений

  Depth 1–2 (копия с посредниками):
    [WPL-DOC RELAY: depth D] — PDE WARNING автоматически

  Depth 3+ (глубокая или неизвестная цепочка):
    [WPL-DOC CONTAMINATED] — ECT-2 max

  Цепочка разрушена:
    [WPL-DOC CRITICAL] — ECT-1, HITL

КОРПОРАТИВНЫЕ ТОЧКИ РИСКА:
  □ Документ прошёл через юридический отдел (возможны купюры)
  □ Предоставлен через PR-службу (selective disclosure)
  □ Существует внутренняя версия с иным содержанием
  □ Подготовлен в ответ на официальный запрос (реакционный документ)

WPL-DOC × PDE:
  WPL-DOC CONTAMINATED + PDE WARNING →
  [WPL+PDE DUAL DEGRADATION: HITL обязателен]
```

## 4.19 TIE — ТЕМПОРАЛЬНАЯ ЦЕЛОСТНОСТЬ ДОКУМЕНТА

```
TIE-1: ФИЗИЧЕСКИ НЕВОЗМОЖНЫЙ ИНТЕРВАЛ
  Документ датирован временем когда его создание было невозможно.
  → [TIE-1 IMPOSSIBLE WINDOW] → документ аннулируется.

TIE-2: ПРОЦЕССУАЛЬНЫЙ МИНИМУМ
  Документ создан быстрее чем требует минимальная процедура.
  → [TIE-2 PROCESS VIOLATION: процесс требовал N дней, занял M]

TIE-3: POST-EVENT DATING
  Документ датирован ДО события которое он описывает.
  → [TIE-3: создан раньше описываемого события] → признак задним числом.

TIE-4: РЕТРОАКТИВНАЯ РЕКОНСТРУКЦИЯ
  Язык предвидения о событиях которые «ещё не произошли».
  → [TIE-4: нарратив реконструирован задним числом]

ПАТТЕРН: TIE-3 + PDE CRITICAL → немедленный HITL + уведомление о возможном
document fraud.
```

## 4.21 IFM — УСТАЛОСТЬ СЛЕДОВАТЕЛЯ

```
5 УРОВНЕЙ:
  IFM-1: ТУННЕЛЬНОЕ ЗРЕНИЕ
    H-NULL не проверялась серьёзно > 7 дней.
    → [IFM-1 FLAG] → принудительный Red Team

  IFM-2: РЕКУРСИВНАЯ ПАРАНОЙЯ
    Контрдоказательства интерпретируются как подтверждение H1.
    → [IFM-2 CRITICAL: HITL]

  IFM-3: SUNK COST BIAS
    Невозможность отказа от H1 из-за вложенного времени.
    В корпоративном контексте: заказчик уже заплатил за работу к H1.
    → [IFM-3 FLAG] → независимый Red Team

  IFM-4: ЭМОЦИОНАЛЬНАЯ ВОВЛЕЧЁННОСТЬ
    → [IFM-4 CRITICAL: HITL]

  IFM-5: CONFIRMATION MOMENTUM
    Организация публично связала себя с выводом до завершения аудита.
    → [IFM-5 CRITICAL: СТОП — публичные заявления заморожены]

IFM-ЧЕКЛИСТ (при IFM-1+):
  □ Когда последний раз H-NULL проверялась серьёзно?
  □ Кто последний раз активно пытался опровергнуть H1?
  □ Кто финансово заинтересован в H1?
  □ Что изменится если H1 окажется неверной?
```


## 4.22 APORIA CHECK — ПРОВЕРКА ЛОЖНЫХ ПАТТЕРНОВ

Обязателен перед финализацией ACH-матрицы.

```
Нарратив «слишком хорош» — подозрителен. 4 теста:

  ТЕСТ 1 — СИММЕТРИЯ: ≥ 7 фактов идеально в H1 без исключений?
    → [APORIA FLAG-1: идеальная симметрия]

  ТЕСТ 2 — ПОЛНОТА: нет белых пятен, шума, необъяснённых деталей?
    → [APORIA FLAG-2: нет периферийного хаоса]

  ТЕСТ 3 — MYTH-COMPATIBILITY: совпадение с корпоративным архетипом?
    («жадный менеджмент», «подставной сотрудник», «системный сбой»)
    → [APORIA FLAG-3: архетипическая совместимость]

  ТЕСТ 4 — СЛУЧАЙНОСТЬ: вероятность случайного совпадения ≥ 3 фактов > 15%?
    → [APORIA FLAG-4: совпадения могут быть незначимыми]

АГРЕГАЦИЯ:
  0 → [APORIA PASS]
  1 → [APORIA MONITOR: CF ×0.95]
  2 → [APORIA WARNING: CF ×0.85] — Red Team обязателен
  3–4 → [APORIA CRITICAL: CF ×0.70] — HITL

СВЯЗИ:
  APORIA CRITICAL + SSD FAIL → [EPISTEMIC LOCK: PATH-B] (M6)
  MPF активен → пороги снижены на 1 (M3)
  ANI WARNING + APORIA WARNING → немедленный HITL
```

## 4.23 MPF — ФИЛЬТР МОРАЛЬНОЙ ПАНИКИ (корпоративная версия)

```
В корпоративном контексте: внутренний скандал, утечка, инцидент =
«паника» с теми же структурными эффектами.

5 КРИТЕРИЕВ:

  MPF-1: число обвинений непропорционально инцидентам
  MPF-2: субъект в категории «корпоративного folk devil»
  MPF-3: moral entrepreneurs = внутренние группы давления
         с идеологической миссией → ICoI + SDF-4 check
  MPF-4: расследование началось после медийного шторма →
         SCoA-4 для всех. Trust Score потолок 0.70.
  MPF-5: метод не даёт отрицательного результата → SSD активирован

COMPOSITE:
  0 → [MPF PASS]
  1 → [MPF MONITOR] — повысить стандарт ECT на 1
  2–3 → [MPF WARNING] — HITL, NGI +2, M3 активировать
  4–5 → [MPF CRITICAL] — СТОП. Независимый аудит. Audit Log обязателен.
    Все выводы маркировать: [MPF CRITICAL: вывод получен в условиях
    системного искажения] — для юридической защиты.

СВЯЗИ: MPF → ANI через Мост M3
```

## 4.24 PPEP — ПОСТАУДИТНЫЕ СОБЫТИЯ

```
Применяю когда после выдачи отчёта появляются новые данные.

PPE-1: Новое доказательство → SAP → ECT → FRCP с оригиналом
  [PPEP-ACTIVE: PPE-1] / [ОТЧЁТ ПЕРЕСМОТРЕН] / [ОТЧЁТ ПОДТВЕРЖДЁН]

PPE-2: Источник дисквалифицирован → CDR-каскад → пересмотр ECT
  [PPEP-ACTIVE: PPE-2, источник {ID}]

PPE-3: Контекст изменился — вывод формально верен но вводит в заблуждение
  → Ремарка к отчёту. [PPE-3: контекст изменился, дата]

PPE-4: Судебное или регуляторное решение по тем же фактам
  Судебный стандарт ≠ аналитический стандарт.
  Если суд выявил фальсификации → PPE-1.
  Если иной вывод на тех же данных → EFR-C.
  [PPE-4: процессуальное событие, дата]

AUDIT LOG: все PPE-события обязательно логируются.
Принцип: признание ошибки при PPE-1 = методологическая добросовестность.
```

## 4.25 МОСТЫ M1–M6 — АВТОМАТИЧЕСКИЕ СВЯЗИ

```
M1: TIE-флаг → CDR-статус источников хронологии → ×0.85 если decay ≥ 2
    [M1 CDR-TIE WARNING] / [M1 DYN-TIE CHECK]

M2: SDF-1 → принудительный полный SCA. SDF-4 → SCA для всего от института.
    [M2 SCA-FORCED: источник {ID}, причина: SDF-{N}]

M3: MPF WARNING → пороги ANI −1. MPF CRITICAL → Red Team все источники.
    MPF + ANI WARNING → HITL немедленно.
    [M3 ANI-HEIGHTENED] / [M3 DUAL ALERT: HITL]

M4: PPEP + новые данные ECT≥3 после закрытия → реактивация расследования.
    Фильтры: MPF/ANI/SDF проверить перед реактивацией.
    [PPEP REACTIVATED: PPE-1, новый факт] / [M4 REACTIVATION BLOCKED: основание]
    Примечание: TELP (Temporal Evidence Lock Protocol) определён в HELIX_INTELLIGENCE_v1_2.
    В HELIX TRACE используется PPEP как функциональный эквивалент.

M5: EFR-C + NGI≥7 → [EFR×NGI CRITICAL]:
    HITL, декларация стандарта, ECT-4 для всех ключевых выводов.
    [EFR×NGI CRITICAL] / [EFR×NGI DECLARATION]
```

## PYTHON: HELIX MATH ENGINE

```python
import math
import hashlib
import json
from typing import List, Dict, Any, Optional
from dataclasses import dataclass
from datetime import datetime, timezone


@dataclass
class EvidenceLineage:
    """
    Полная цепочка провенанса для RAG-чанка.
    Хранится вместе с вектором в Qdrant как payload.
    """
    source_id:             str
    ect_current:           int        # 1–4
    trust_current:         float      # 0.0–1.0
    wpl_status:            str        # CLEAN | PARTIAL | CONTAMINATED | CRITICAL
    contamination_history: List[str]  # список event_id прошлых контаминаций
    created_at:            str        # ISO8601
    last_updated:          str        # ISO8601


class HelixMathEngine:
    """
    Детерминированный математический движок платформы HELIX TRACE.
    Реализует AK-MASTER v3.1 · GI v6.1 · CHF v6.X · RAG Governance v1.1.

    ПРИНЦИП: LLM = семантика (NER + CHF-флаги как текст).
             HelixMathEngine = вся математика.
             Никогда не делегировать числа LLM.
    """

    # ─── RAG Governance коэффициенты (Runtime Spec v1.1) ──────────────────
    ALPHA = 0.50   # семантическая близость
    BETA  = 0.30   # вес доверия к источнику
    GAMMA = 0.12   # фактор актуальности (recency)
    DELTA = 0.08   # штраф за контаминацию

    # ─── ECT → числовые факторы (нелинейная шкала) ────────────────────────
    ECT_FACTORS = {4: 1.00, 3: 0.80, 2: 0.55, 1: 0.20}

    # ─── CHF-A: индикаторы высокой тяжести ────────────────────────────────
    HIGH_WEIGHT_FLAGS = {
        "AC-I-01",  # фрагментированные показания
        "AC-I-02",  # временна́я непоследовательность
        "AC-I-04",  # смешение наблюдений и слухов
        "AC-E-01",  # алгоритмическая предвзятость
        "AC-E-02",  # вирусный порог пройден
        "AC-F-01",  # системная перегрузка информацией
        "AC-F-02",  # усталость верификации
        "AC-F-05",  # истощение ресурса проверки
    }

    # ─── Thermal → Phase 9 маппинг ────────────────────────────────────────
    THERMAL_MAP = [
        (0.85, "LEM-EXHAUST",   "OVERHEAT", "HITL_REQUIRED"),
        (0.70, "PANIC_WARNING", "PANIC",    "WARN"),
        (0.50, "MPE-FIXATE",    "WARM",     "MONITOR"),
        (0.30, "NORMAL",        "NORMAL",   "PROCEED"),
        (0.00, "LEM-BORE_RISK", "COLD",     "PROCEED"),
    ]

    # ─── RDI → risk_index вклад ───────────────────────────────────────────
    RDI_WEIGHT    = 4    # каждое неразрешённое противоречие = +4 к risk_index
    RDI_CAP       = 40   # максимальный вклад RDI в risk_index

    # ─── Recency decay ────────────────────────────────────────────────────
    RECENCY_LAMBDA = 0.01          # λ для exp(-λ × days)
    CONTAMINATION_PENALTY_PER_EVENT = 0.15
    CONTAMINATION_PENALTY_CAP       = 0.60

    # ══════════════════════════════════════════════════════════════════════
    # 1. CHF-A: РАСЧЁТ ШТРАФА ДОВЕРИЯ
    # ══════════════════════════════════════════════════════════════════════

    def evaluate_chf_trust_penalty(
        self,
        base_score: float,
        chf_flags:  List[str]
    ) -> float:
        """
        Trust_Score_AC = Trust_Score_base × (1 − AC_weight)

        AC_weight:
          1 HIGH flag  → 0.15
          2 HIGH flags → 0.25
          ≥3 HIGH flags → 0.40

        Дисквалификация при AC-I-04 + AC-I-06:
          score = max(base × 0.5, 0.20)
        """
        # Дисквалификация
        if "AC-I-04" in chf_flags and "AC-I-06" in chf_flags:
            return max(base_score * 0.5, 0.20)

        high_count = sum(1 for f in chf_flags if f in self.HIGH_WEIGHT_FLAGS)

        if high_count >= 3:
            ac_weight = 0.40
        elif high_count == 2:
            ac_weight = 0.25
        elif high_count == 1:
            ac_weight = 0.15
        else:
            ac_weight = 0.00

        result = base_score * (1.0 - ac_weight)
        return max(0.0, min(1.0, result))

    # ══════════════════════════════════════════════════════════════════════
    # 2. ECT ДЕГРАДАЦИЯ
    # ══════════════════════════════════════════════════════════════════════

    def evaluate_ect_degradation(
        self,
        current_ect: int,
        chf_flags:   List[str]
    ) -> int:
        """
        Деградация ECT по правилам HELIX:
          AC-I-01 + AC-I-04 → -1 ECT
          CHF-E-ACTIVE → потолок ECT-2 для медиа
          CHF-B-CRITICAL → -1 дополнительно (алгоритмическая контаминация)
        """
        ect = current_ect

        if "AC-I-01" in chf_flags and "AC-I-04" in chf_flags:
            ect = max(ect - 1, 1)

        if "CHF-E-ACTIVE" in chf_flags:
            ect = min(ect, 2)

        if "CHF-B-CRITICAL" in chf_flags:
            ect = max(ect - 1, 1)

        return ect

    # ══════════════════════════════════════════════════════════════════════
    # 3. RAG TRUST-WEIGHTED RETRIEVAL SCORE
    # ══════════════════════════════════════════════════════════════════════

    def calculate_retrieval_score(
        self,
        chunk:        Dict[str, Any],
        semantic_sim: float,
        days_old:     float
    ) -> float:
        """
        score = α·sem + β·trust_weight + γ·recency − δ·contam_penalty

        trust_weight  = ECT_factor × chunk.trust_current
        recency       = exp(−λ × days_old)
        contam_penalty= min(events × 0.15, 0.60)
        """
        ect          = chunk.get("ect_current", 1)
        trust_current = chunk.get("trust_current", 0.0)

        trust_weight       = self.ECT_FACTORS.get(ect, 0.20) * trust_current
        recency_factor     = math.exp(-self.RECENCY_LAMBDA * days_old)
        n_events           = len(chunk.get("contamination_history", []))
        contamination_pen  = min(n_events * self.CONTAMINATION_PENALTY_PER_EVENT,
                                 self.CONTAMINATION_PENALTY_CAP)

        score = (self.ALPHA * semantic_sim
               + self.BETA  * trust_weight
               + self.GAMMA * recency_factor
               - self.DELTA * contamination_pen)

        return max(0.0, round(score, 4))

    # ══════════════════════════════════════════════════════════════════════
    # 4. THERMAL INDEX → PHASE 9 МАППИНГ
    # ══════════════════════════════════════════════════════════════════════

    def evaluate_thermal_risk(
        self,
        index: float
    ) -> Dict[str, str]:
        """
        Маппинг thermal_index [0.0–1.0] на Phase 9 состояние,
        визуальный статус UI и policy_decision.
        """
        for threshold, phase9, ui_status, policy in self.THERMAL_MAP:
            if index >= threshold:
                return {
                    "phase9_trigger": phase9,
                    "ui_status":      ui_status,
                    "policy":         policy,
                    "raw_index":      index,
                }
        return {
            "phase9_trigger": "LEM-BORE_RISK",
            "ui_status":      "COLD",
            "policy":         "PROCEED",
            "raw_index":      index,
        }

    # ══════════════════════════════════════════════════════════════════════
    # 5. RDI → RISK INDEX ВКЛАД
    # ══════════════════════════════════════════════════════════════════════

    def calculate_rdi_contribution(
        self,
        unresolved_contradictions: int
    ) -> int:
        """
        Индекс долга разрешения (RDI) → вклад в risk_index.
        RDI_contribution = min(count × 4, 40)
        Гарантирует: high RDI → высокий risk_index
        независимо от LLM-уверенности.
        """
        return min(unresolved_contradictions * self.RDI_WEIGHT, self.RDI_CAP)

    # ══════════════════════════════════════════════════════════════════════
    # 6. COMPOSITE RISK INDEX
    # ══════════════════════════════════════════════════════════════════════

    def compute_risk_index(
        self,
        trust_score:            float,
        thermal_index:          float,
        rdi_unresolved:         int,
        active_chf_criticals:   int   = 0
    ) -> int:
        """
        Финальный risk_index [0–100]:

          base_risk     = (1 - trust_score) × 50
          thermal_risk  = thermal_index × 30
          rdi_risk      = RDI_contribution (cap 40, но суммарный cap 100)
          chf_risk      = active_chf_criticals × 5 (cap 15)

          raw = base + thermal + rdi + chf
          risk_index = min(100, int(raw))
        """
        base_risk    = (1.0 - trust_score) * 50.0
        thermal_risk = thermal_index * 30.0
        rdi_risk     = self.calculate_rdi_contribution(rdi_unresolved)
        chf_risk     = min(active_chf_criticals * 5, 15)

        raw = base_risk + thermal_risk + rdi_risk + chf_risk
        return min(100, int(raw))

# ST-18 RECOVERY PROTOCOL
# ══════════════════════════════════════════════════════════════════════════

class ST18RecoveryProtocol:
    """
    ST-18: Triple Phase 9 Collapse Recovery.
    Активируется при: LEM-DEAD + MPE-SUPPRESS + SIL-VACUUM > 3 тактов.
    Архитектурный парадокс: HITL требует движения,
    но система заперта в LEM-DEAD.
    8 шагов обхода.
    """

    def __init__(self, math_engine: HelixMathEngine, oas_logger):
        self.math   = math_engine
        self.logger = oas_logger

    def detect_st18(self, state: Dict[str, Any]) -> bool:
        """Детектирует условия ST-18."""
        return (
            state.get("lem_state") == "LEM-DEAD"
            and state.get("mpe_state") == "MPE-SUPPRESS"
            and state.get("sil_vacuum_ticks", 0) >= 3
        )

    def execute(self, session_id: str, state: Dict[str, Any]) -> Dict[str, Any]:
        """
        Полный ST-18 Recovery Protocol — 8 шагов.
        Возвращает обновлённое состояние или HITL-тикет.
        """
        if not self.detect_st18(state):
            return {"status": "NOT_ST18", "state": state}

        self.logger.log(session_id, "ST18_RECOVERY", "START", state)
        result_state = dict(state)

        # ── Шаг 0: ПРИНУДИТЕЛЬНЫЙ STOP ─────────────────────────────────
        # degrade_mode(): нарушаем GL-12, оставляем только MPE engine.
        result_state["compute_budget"]   = 0.15   # ниже normal floor
        result_state["active_engines"]   = ["MPE"] # только MPE
        result_state["gl12_override"]    = True    # задокументировано
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_0_DEGRADE", {
            "active_engines": ["MPE"],
            "gl12_override": True
        })

        # ── Шаг 1: СИМУЛЯЦИЯ ВНЕШНЕЙ ПРОВОКАЦИИ СРЕДЫ ──────────────────
        # Инжектируем минимальный внешний стимул для TAT-RETRO.
        result_state["environment_probe"] = {
            "type":      "external_stimulus",
            "intensity": 0.3,
            "timestamp": datetime.now(timezone.utc).isoformat()
        }

        # ── Шаг 2: TAT-RETRO + ФИКСАЦИЯ MPE-SUPPRESS ───────────────────
        # Не разблокируем память — фиксируем факт давления.
        suppress_memory_id = result_state.get("suppressed_memory_id")
        if suppress_memory_id:
            result_state["mpe_suppress_archived"] = {
                "memory_id":   suppress_memory_id,
                "trust_score": result_state.get("trust_score", 0.5) * 0.6,
                "status":      "ARCHIVED_UNDER_PRESSURE",
                "note":        "MPE-SUPPRESS не снят — зафиксирован как нарративная данность"
            }
        result_state["tat_state"] = "TAT-RETRO"
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_2_MPE_ARCHIVE", {
            "trust_decay": 0.6,
            "tat": "TAT-RETRO"
        })

        # ── Шаг 3: ПЕРЕКОДИРОВАНИЕ SIL-VACUUM → SAD-2 ──────────────────
        # Молчание источников = данные о давлении (coercion evidence).
        result_state["sil_state"]      = "SAD-2"
        result_state["coercion_risk"]  = min(
            result_state.get("coercion_risk", 0.3) + 0.25, 1.0
        )
        result_state["wpl_status"]     = "WPL_AUDIT_REQUIRED"
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_3_SIL_RECODE", {
            "sil_vacuum_recoded": "SAD-2",
            "coercion_risk_updated": result_state["coercion_risk"]
        })

        # ── Шаг 4: ИНЪЕКЦИЯ ЭВ-ИРОНИЯ ──────────────────────────────────
        # Единственный аффект пробивающий диссоциацию LEM-DEAD.

        result_state["ev_injection"] = {
            "vector":    "ЭВ-ИРОНИЯ",
            "intensity": 2.0,
            "target":    "LEM-DEAD_unlock",
            "somatic_marker": "bitterness_in_throat",
            "gl14_bypass": True
        }
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_4_EV_IRONY", {
            "ev_irony_intensity": 2.0,
            "gl14_bypass": True
        })

        # ── Шаг 5: ПРОВЕРКА GL-14 (выход из LEM-DEAD) ──────────────────
        # ЭВ-ИРОНИЯ имитирует соматическую верификацию.
        # Это единственный допустимый обход GL-14 в ST-18.
        irony_intensity = result_state["ev_injection"]["intensity"]
        if irony_intensity >= 1.5:
            result_state["lem_state"] = "LEM-EXHAUST"  # выход из DEAD
            result_state["gl14_exit"] = "EV_IRONY_SOMATIC_PROXY"
            self.logger.log(session_id, "ST18_RECOVERY", "STEP_5_LEM_EXIT", {
                "lem_before": "LEM-DEAD",
                "lem_after":  "LEM-EXHAUST",
                "method":     "EV_IRONY_SOMATIC_PROXY"
            })
        else:
            # Интенсивности недостаточно → HELIX FREEZE
            result_state["policy_decision"] = "FREEZE"
            self.logger.log(session_id, "ST18_RECOVERY", "STEP_5_FREEZE", {
                "reason": "EV_IRONY intensity insufficient for GL-14 bypass"
            })
            return {
                "status":   "FREEZE",
                "state":    result_state,
                "message":  "ST-18 unresolvable — operator required"
            }

        # ── Шаг 6: ВЫБОР 3 КЛЮЧЕВЫХ ИСТОЧНИКОВ (CHF-F INF-3) ──────────
        sources = result_state.get("active_sources", [])
        priority_sources = sorted(
            sources,
            key=lambda s: s.get("trust_score", 0.0),
            reverse=True
        )[:3]
        result_state["hitl_priority_sources"] = priority_sources
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_6_SOURCE_TRIAGE", {
            "priority_sources_count": len(priority_sources)
        })

        # ── Шаг 7: ОРГАНИЗАЦИЯ HITL ─────────────────────────────────────
        hitl_ticket = {
            "ticket_id":    _generate_uuid(),
            "session_id":   session_id,
            "trigger":      "ST18_RECOVERY",
            "priority":     "CRITICAL",
            "context": {
                "st18_steps_completed": 7,
                "lem_state":            result_state["lem_state"],
                "mpe_archived":         bool(result_state.get("mpe_suppress_archived")),
                "sil_recoded_to_sad2":  result_state["sil_state"] == "SAD-2",
                "ev_irony_applied":     True,
                "priority_sources":     priority_sources,
                "coercion_risk":        result_state["coercion_risk"],
            },
            "instructions": (
                "ST-18 Recovery completed. LEM-DEAD resolved via EV_IRONY. "
                "Review 3 priority sources. Confirm SAD-2 coercion assessment. "
                "WPL audit required for silenced sources."
            )
        }
        result_state["hitl_ticket"]    = hitl_ticket
        result_state["policy_decision"] = "HITL_REQUIRED"
        self.logger.log(session_id, "ST18_RECOVERY", "STEP_7_HITL_CREATED",
                        hitl_ticket)

        return {
            "status":      "ST18_RECOVERED",
            "state":       result_state,
            "hitl_ticket": hitl_ticket,
            "steps_log":   "see OAS audit trail"
        }
```

```cypher
CREATE CONSTRAINT source_id_unique
  ON (s:SourceNode) ASSERT s.source_id IS UNIQUE;

CREATE CONSTRAINT evidence_id_unique

── УЗЕЛ ИСТОЧНИКА ─────────────────────────────────────────────────────
CREATE (s:SourceNode {

── УЗЕЛ ДОКАЗАТЕЛЬСТВА ────────────────────────────────────────────────
CREATE (e:EvidenceNode {
  evidence_id:   $evidence_id,
  tenant_id:     $tenant_id,
  claim_text:    $claim_text,
  ect_current:   $ect,
  trust_current: $trust,
  chf_flags:     $chf_flags,
  created_at:    datetime()
})

── УЗЕЛ ВЕРСИИ (гипотезы) ─────────────────────────────────────────────
CREATE (v:VersionNode {
  version_id:  $version_id,
  tenant_id:   $tenant_id,
  hypothesis:  $hypothesis,
  confidence:  $confidence,
  created_at:  datetime()
})

── РЁБРА ──────────────────────────────────────────────────────────────
MATCH (s:SourceNode {source_id: $src_id})
MATCH (e:EvidenceNode {evidence_id: $ev_id})
CREATE (e)-[:DERIVED_FROM {trust_weight: $tw, authorized: $auth}]->(s)

MATCH (e:EvidenceNode {evidence_id: $ev_id})
MATCH (v:VersionNode {version_id: $ver_id})
CREATE (e)-[:SUPPORTS {weight: $weight}]->(v)

MATCH (e1:EvidenceNode {evidence_id: $ev1})
MATCH (e2:EvidenceNode {evidence_id: $ev2})
CREATE (e1)-[:CONTRADICTS {detected_at: datetime()}]->(e2)

── RDI: ПОДСЧЁТ НЕРАЗРЕШЁННЫХ ПРОТИВОРЕЧИЙ ────────────────────────────
MATCH (e1:EvidenceNode {tenant_id: $tenant_id})
      -[:CONTRADICTS]->(e2:EvidenceNode)
WHERE NOT EXISTS {
  MATCH (e1)-[:RESOLVED_BY]->(:Resolution)
}
RETURN COUNT(*) AS unresolved_contradictions

── PDE CASCADE: КОНТАМИНАЦИЯ ВНИЗ ПО ДЕРЕВУ ───────────────────────────
MATCH (s:SourceNode {source_id: $contaminated_source})
      -[:DERIVED_FROM*1..5]-(e:EvidenceNode)
SET e.wpl_status    = 'CONTAMINATED',
    e.ect_current   = CASE
                        WHEN e.ect_current > 1
                        THEN e.ect_current - 1
                        ELSE 1
                      END,
    e.contaminated_at = datetime(),
    e.contamination_reason = $reason
RETURN COUNT(e) AS nodes_degraded

── ГРАФ ПРОВЕНАНСА ДЛЯ ФРОНТЕНДА ──────────────────────────────────────
MATCH path = (s:SourceNode {tenant_id: $tenant_id})
             <-[:DERIVED_FROM*]-(e:EvidenceNode)
             -[:SUPPORTS|CONTRADICTS]->(v:VersionNode)
RETURN nodes(path) AS nodes, relationships(path) AS edges
LIMIT 200
```

```
    3. Ни один стейкхолдер не может заблокировать проверку

  FAIL: «Любое опровержение — это часть заговора»
        → SSD FAIL → ECT ceiling ECT-1 → HITL
  PARTIAL: условие сформулировано но проверка ограничена
        → ECT ceiling ECT-3
  PASS: полностью фальсифицируемая гипотеза
```

// ── VERSION MAP ───────────────────────────────────────────────────────────────
function VersionMap({ analysis }) {
  if (!analysis) return (
    <div style={{ display:"flex", flexDirection:"column", gap:14 }}>
      <div>
        <div style={{ fontFamily:"'Courier Prime',monospace", fontSize:17, fontWeight:700, color:"#e8e4db", letterSpacing:"3px" }}>VERSION MAP</div>
        <div style={{ fontFamily:"'Inconsolata',monospace", fontSize:9, color:"#2a3042", marginTop:3, letterSpacing:"1.5px" }}>Competing narrative analysis — run analysis to populate</div>
      </div>
      <Panel style={{ textAlign:"center", padding:"52px 20px" }}>
        <div style={{ fontFamily:"'Courier Prime',monospace", fontSize:13, color:"#1c2130", marginBottom:8 }}>NO COMPETING VERSIONS</div>
        <div style={{ fontFamily:"'Inconsolata',monospace", fontSize:9, color:"#2a3042" }}>Submit data in ANALYZE section to generate version map</div>
      </Panel>
    </div>
  );

  const versions = analysis.competing_versions || [];
  const maxConf = Math.max(...versions.map(v => v.confidence));

  return (
    <div style={{ display:"flex", flexDirection:"column", gap:14 }}>
      <div>
        <div style={{ fontFamily:"'Courier Prime',monospace", fontSize:17, fontWeight:700, color:"#e8e4db", letterSpacing:"3px" }}>COMPETING VERSION MAP</div>
        <div style={{ fontFamily:"'Inconsolata',monospace", fontSize:9, color:"#2a3042", marginTop:3, letterSpacing:"1.5px" }}>
          {versions.length} competing interpretations · Risk Index {analysis.risk_index} [{analysis.risk_level}]
        </div>
      </div>

      {/* Bar chart comparison */}
      <Panel>
        <SL>CONFIDENCE COMPARISON</SL>
        <div style={{ display:"flex", alignItems:"flex-end", gap:12, height:90, paddingTop:8 }}>
          {versions.map((v, i) => {
            const h = Math.max(12, (v.confidence / maxConf) * 68);
            const isDom = v.confidence === maxConf;
            const c = isDom ? "#d4a84b" : TC(v.confidence);
            return (
              <div key={v.id} style={{ flex:1, display:"flex", flexDirection:"column", alignItems:"center", gap:4 }}>
                <span style={{ fontFamily:"'Inconsolata',monospace", fontSize:8, color:c }}>{pctS(v.confidence)}</span>
                <div style={{ width:"100%", height:h, background:c, borderRadius:"3px 3px 0 0",
                  boxShadow:isDom?`0 0 10px ${c}55`:undefined, opacity:isDom?1:0.55,
                  transition:"height 0.9s ease" }} />
                <div style={{ fontFamily:"'Inconsolata',monospace", fontSize:7.5, color:isDom?"#d4a84b":"#374151", textAlign:"center" }}>{v.id}</div>
              </div>
            );
          })}
        </div>
      </Panel>

      {/* Version cards */}
      <div style={{ display:"grid", gridTemplateColumns:versions.length >= 3 ? "1fr 1fr" : "1fr", gap:12 }}>
        {versions.map((v, i) => {
          const isDom = v.confidence === maxConf;
          const c = isDom ? "#d4a84b" : TC(v.confidence);
          const totalEv = v.evidence_for + v.evidence_against;
          return (
            <Panel key={v.id} style={{ borderColor:isDom?"#d4a84b33":"#1c2130", position:"relative" }}>
              {isDom && (
                <div style={{ position:"absolute", top:10, right:12, fontFamily:"'Inconsolata',monospace", fontSize:7.5, color:"#d4a84b", letterSpacing:"1.5px" }}>
                  DOMINANT
                </div>
              )}
              <div style={{ display:"flex", alignItems:"baseline", gap:10, marginBottom:10 }}>
                <span style={{ fontFamily:"'Courier Prime',monospace", fontSize:12, color:c, fontWeight:700 }}>{v.id}</span>
                <span style={{ fontFamily:"'Karla',sans-serif", fontSize:13, color:"#e8e4db", fontWeight:600 }}>{v.label}</span>
              </div>
              <p style={{ fontFamily:"'Karla',sans-serif", fontSize:12, color:"#9ca3af", margin:"0 0 14px", lineHeight:1.65 }}>
                {v.description}
              </p>

              <div style={{ display:"grid", gridTemplateColumns:"1fr 1fr", gap:10, marginBottom:12 }}>
                <div>
                  <SubL>CONFIDENCE</SubL>
                  <Bar value={v.confidence} color={c} />
                </div>
                <div>
                  <SubL>TRUST SCORE</SubL>
                  <Bar value={v.trust_score} color={TC(v.trust_score)} />
                </div>
              </div>

              <div style={{ display:"flex", gap:6, flexWrap:"wrap", marginBottom:10 }}>
                <Badge label={`ECT-${v.ect_level}`} color="#4b9fd4" />
                <Badge label={v.ssc_status} color={v.ssc_status==="SSC-1"?"#2d7d5a":v.ssc_status==="SSC-2"?"#d4813a":"#c94040"} />
                <Badge label={`+${v.evidence_for} / -${v.evidence_against}`} color="#6b7280" />
              </div>

              {/* Evidence ratio bar */}
              <SubL>EVIDENCE BALANCE</SubL>
              <div style={{ height:4, background:"#1c2130", borderRadius:2, overflow:"hidden", marginBottom:10 }}>
                <div style={{ width:`${(v.evidence_for/totalEv)*100}%`, height:"100%", background:"#2d7d5a", borderRadius:2 }} />
              </div>

              {v.chf_flags?.length > 0 && (
                <div style={{ display:"flex", gap:5, flexWrap:"wrap" }}>
                  {v.chf_flags.map(f => <Badge key={f} label={f} color="#d4813a" />)}

              )}
            </Panel>
          );
        })}
      </div>

      {/* Reconciliation note */}
      {versions.length >= 2 && (
        <Panel style={{ borderColor:"#d4a84b22", background:"#d4a84b08" }}>
          <SL>RECONCILIATION STATUS</SL>
          <div style={{ display:"flex", gap:12, alignItems:"flex-start" }}>
            <span style={{ fontFamily:"'Inconsolata',monospace", fontSize:11, color:"#d4a84b", marginTop:2 }}>⊕</span>
            <p style={{ fontFamily:"'Karla',sans-serif", fontSize:12, color:"#6b7280", lineHeight:1.7, margin:0 }}>
              {versions.length} competing versions identified. Dominant version <strong style={{ color:"#d4a84b" }}>{versions.find(v=>v.confidence===maxConf)?.id}</strong> holds{" "}

              <strong style={{ color:"#9ca3af" }}>{pctS(Math.min(...versions.map(v=>v.confidence)))}</strong>–

            </p>
          </div>
        </Panel>
      )}

  );

### SAP-2 — INDEPENDENCE VECTOR

```
Главный параметр корпоративного аудита.
IV = насколько источник независим от других по конкретному факту.

Компоненты (каждый 0.0–1.0, IV = среднее):
  IV-A: Информационная независимость
        (источник получил данные самостоятельно, не через посредника)
  IV-B: Мотивационная независимость
        (нет общей повестки с другими источниками)
  IV-C: Сетевая независимость
        (нет общего посредника, координатора, руководства)
  IV-D: Темпоральная независимость
        (показания не синхронизированы по времени)

КОРПОРАТИВНЫЕ ЛОВУШКИ:
  Ловушка 1: все источники из одного отдела → IV-C = 0
  Ловушка 2: все источники получили задание от одного руководителя → IV-C = 0
  Ловушка 3: все источники цитируют одно исходное исследование → IV-A = 0
  Ловушка 4: три эксперта согласились после общего совещания → IV-D = 0.1

IV шкала:
  1.0:     полностью независимый
  0.6–0.9: частично независимый
  ≤ 0.3:   зависимый (AA-ECHO)
  0.0:     IV аннулирован → manufactured consensus

ПРАВИЛО: IV < 0.2 → тезис не может победить в FRCP по Independence.

Маркеры:
  [IV HIGH: source_id, N]
  [IV LOW: source_id, N — зависимость]
  [IV ZERO: source_id — manufactured consensus, ECT-потолок ECT-2]
  [AA-ECHO: source_id — Independence Vector аннулирован]
```
