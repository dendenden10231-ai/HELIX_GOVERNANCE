## Правило этих паспортов

**Ни одного числа без команды рядом.** Документ стареет, команда — нет.

Это не педантизм. Прежняя редакция паспортов была составлена 13–19
августа и к 21-му разошлась с действительностью сильно: AK-MASTER
заявлял «2817 прошло, 12 упало» — сейчас **6 514 прошло, 0 упало**;
«173 маршрута» — сейчас **189**; Мистер Хеликс называл «571 тест» и
«112+ капсул» — сегодня **99 капсул**, а тесты входят в общий прогон.

Причём паспорт Мистера Хеликса **сам предписывал это правило**: «не
верить числу в документе, запустить — только так число тестов
достоверно; минимум дважды находились расхождения между записанным
числом и реальным подсчётом». Теперь оно применено ко всем трём.

Двенадцать падавших тестов, которые прежний паспорт объяснял конфликтом
окружения, больше не воспроизводятся — **его собственный диагноз
подтвердился сам собой**.

## Что проверить одной командой

```bash
python3 -m engine.coverage_validator                    # AK-MASTER: канон
python3 -m mr_helix.engine.capsule_contract_audit       # Мистер Хеликс: контракт
python3 -m helix_pipeline.engine.helix_contract_audit   # HELIX: контракт
python3 -m pytest -q && python3 -m pytest helix_pipeline/tests -q
```

Ожидаемое на 21.08: AK-MASTER 14 блоков (13 принуждаются кодом, 1 —
решение не принуждать), Мистер Хеликс 99 капсул / 583 состояния / 0
недостижимых, HELIX 922 состояния / 0 недостижимых, тесты 4 360 + 2 154.

## Граница честности — одна на все три

Контрактный аудит доказывает, что каждое состояние, которое
спецификация называет прямым текстом, **код умеет вернуть**. Он **не**
доказывает, что оно возвращается при правильных условиях, и **не**
является сертификацией под нагрузкой.

И главное, что сказано в каждом из трёх: **независимой верификации нет**.
Всё доказательство происходит из одного репозитория одного человека. Это
названо главной структурной слабостью собственным аудитом продукта, а не
признано под давлением.
