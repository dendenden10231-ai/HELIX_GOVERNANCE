## Найдено и починено в этой сессии

### §4.19 TIE — TIE-3 POST-EVENT DATING / TIE-4 RETROACTIVE RECONSTRUCTION

**Файл**: `helix_pipeline/engine/tie_trace.py` (новый), подключён как
`gi.tie_trace`. Коммит `5fbf3fa`.

`trace_vector.py` заявлял, что TIE полностью закрывается общим `gi.tie`
(GI v6.2 Патч 48) без переопределения для TRACE. Неверно: TRACE §4.19 даёт
свою нумерацию TIE-1..4, и TIE-3 (документ датирован до события, но
метаданные показывают более позднее фактическое создание — признак
подделки даты) и TIE-4 (язык предвидения о ещё не произошедших событиях)
не имеют эквивалента в `tie.py` (тот закрывает TA-1..3 — плотность
событий, пропущенный период, причинность; другая тема). Критическая
комбинация спеки «TIE-3 + PDE CRITICAL → немедленный HITL, уведомление о
document fraud» тоже отсутствовала. Построено, 17 тестов.

### §4.18 WPL-DOC — цепочка передачи документа

**Файл**: `helix_pipeline/engine/wpl_doc.py` (новый), подключён как
`gi.wpl_doc`. Коммит `e5a21d5`.

Раздел не был реализован нигде — не переопределён по ошибке и не описан
как покрытый, а просто пропущен целиком. `gi.wpl` (Патч 65) — про цепочку
ПОКАЗАНИЙ (девятиполевая штрафная модель для человека, рассказывающего о
событии); §4.18 — целочисленная ГЛУБИНА передачи самого ДОКУМЕНТА
(0/1-2/3+/сломана, без весовой формулы) плюс четыре корпоративных флага
риска (юридический отдел, PR-служба, внутренняя версия, реакционный
документ). Построено, включая связку WPL-DOC × PDE (CONTAMINATED + PDE
WARNING+ → DUAL DEGRADATION, HITL). 14 тестов.

### Приложение C — SCA корпоративные комбинации

**Файл**: `helix_pipeline/engine/sca_trace.py` (новый), подключён как
`gi.sca_dual_flag` / `gi.sca_backdated_check`. Коммит `c3663c3`.

`sca.py` (Патч 36) реализует четыре теста SCA и базовую агрегацию — уже
сверено верным. TRACE Приложение C добавляет два корпоративных правила
поверх тех же тестов: SCA DUAL FLAG (SCA-1+SCA-2 одновременно → ECT-2 max,
отдельно от общей агрегации «2+ флага») и «задним числом» (SCA-2 в
значении «создан после события» + SCA-3 в значении «ссылки на будущее» →
PDE FAILED + HITL_REQUIRED). Ни то, ни другое не существовало в коде.
Построено, 10 тестов.

## Находки из более ранних сессий (перепроверены, подтверждены)

`AUDIT_TRACKER.md` до этой сессии ошибочно говорил «TRACE не начато
построчно» — на деле `gi62_patch_manifest.yaml::trace_layer` уже содержал:

| Находка | Файл | Суть |
|---|---|---|
| `SAP-2-IV-COMPONENTS` | `independence_vector.py` | Independence Vector разложен на IV-A/B/C/D + 4 корпоративные ловушки |
| `TRACE-4.11-CORPORATE-FA` | `corporate_fa.py` | §4.11 отсутствовал полностью; построены 8 корпоративных FA-режимов, номерная коллизия с GI62 Appendix C задокументирована и НЕ слита |
| `TRACE-4.12-CPX` | `cpx_trace.py` | TraceVector ошибочно подключал матрицу INT §3.29; построена третья самостоятельная матрица |
| `TRACE-TEXT-CLASSIFIER` | `trace_classifier.py` | TRACE запускалась только по структурированным входам; построен классификатор из сырого текста (PARTIAL осознанно — 7 из 11 полей content-derivable) |

Плюс в `trace_vector.py` и `int_layer`:
- HITL-классификация (`hitl_matrix.py`) — TRACE-эксклюзивные условия
  проваливались в `unknown`, починено.
- Структура отчёта (`report_structure.py`) — TRACE §8 ошибочно бралась от
  INTELLIGENCE, починено.
- CHF (`chf.py`) — отсутствовал полностью для обоих продуктов, построен
  как общая формула (Appendix E весов дословно совпадает у INT и TRACE).
- Risk Index (`risk_index.py`) — отсутствовал полностью; построен с
  явным параметром `spec` (`"intelligence"`/`"trace"`), потому что два
  «потолочных» бонуса (ICoI RISK +20, MANIPULATION RISK +15) имеют разные
  условия срабатывания в двух спеках — без дефолта, чтобы не занизить
  риск для одного продукта молча.

Все перепроверены в этой сессии — подтверждены корректными, без правок.
