# HELIX: замер статистики на больших наборах (24.10.2026, расход 0 $)

Требование владельца: «никаких одиночных примеров — статистику». Ниже два замера на
целых наборах. Каждый воспроизводится скриптом из `scripts/`.

## 1. statcheck — пересчёт p в статьях (`статистика_аудит.py`)

**Набор.** Эталонные данные авторов statcheck (Nuijten, проект effectivity-statcheck,
GitHub/OSF). Это результаты статистических тестов из психологических журналов, у каждого
есть вердикт программы statcheck на R: «несогласие p» и «решающая ошибка». Сверено
**144 631 результат** (F, t, χ², r, z).

Не сверены 4 364 строки:
- 2 824 — нечисловые записи;
- 1 035 — запись вида «F < 1», где знак стоит у самой статистики;
- 301 — редкие тесты Q;
- 4 — ошибки расчёта.

**Арифметика верна.** Наш пересчёт p совпал с эталоном до 0,1 % в 97–100 % результатов,
медиана расхождения 10⁻¹⁴. Оставшиеся 2–3 % — односторонние тесты, которые эталон
учитывает по тексту статьи.

**Найден и исправлен дефект логики.** Функция не знала знак в записи «p < .001» и
сравнивала её как «p = 0,001». Добавлены параметр `знак` («=», «<», «>») и три
документированных правила statcheck:
- «p = .05» считается значимым;
- «p = .000» — всегда ошибка;
- решающая ошибка засчитывается только при несогласии p с расчётом.

Кроме того, отрицательные F и χ² отмечаются как ошибка записи.

| | Было | Стало |
|---|---|---|
| **любое несогласие p** (эталон: 10 095) | | |
| совпали с эталоном | 3 795 | **10 066** |
| лишние тревоги | **59 107** | **0** |
| пропущено | 6 300 | 29 |
| точность / полнота | 0,060 / 0,376 | **1,000 / 0,997** |
| **решающая ошибка** (значимость перепутана; эталон: 1 222) | | |
| совпали | 761 | **1 191** |
| лишние тревоги | 8 570 | **0** |
| пропущено | 461 | 31 |
| точность / полнота | 0,082 / 0,623 | **1,000 / 0,975** |
| общее согласие с эталоном | 0,548 | **0,9998** |

**Что это значит и чего не значит.** До правки модуль на настоящих статьях давал
59 тысяч ложных тревог. Хорошо, что он ни к чему не был подключён. Теперь он решает
так же, как эталонная программа, в 99,98 % случаев. Правила взяты из документации
statcheck, а не подобраны под данные. Но это согласие с эталоном, а не с истиной. Точность
самого statcheck против ручной проверки описана у авторов (Nuijten и др., 2016,
приложение A), здесь она не мерилась.

**Чего всё ещё нет.** Разбора текста: функция принимает готовые числа. Для HELIX нужно
вытаскивать записи вида «t(28) = 2,20, p = .03» из статьи. Это следующий шаг, и его тоже
надо мерить на этом наборе: в столбце `raw` лежит исходная запись.

## 2. Меры эффекта из аннотаций (`научная_статистика.py`, работает на сайте)

**Набор.** 2 000 свежих аннотаций PubMed (2015–2024, сортировка по дате) с отношением
рисков и доверительным интервалом. Всего таких в PubMed 189 835.

| | Значение |
|---|---|
| аннотаций с найденной мерой | 1 790 из 1 933 с «95 % ДИ» (0,93) |
| мер найдено | 4 827 (OR 2 592, HR 1 335, RR 480, aOR 279, aHR 88, прочие 53) |
| **точность:** 100 случайных мер (зерно 8888) сверены с текстом аннотации | **100 из 100**: число и интервал верны; 95 % нижняя граница — 0,96 |
| **полнота:** кандидатов «число + 95 % ДИ» в тексте | 5 134, разбор взял 4 551 (0,886) |
| из 30 случайных невзятых — настоящие пропуски отношений | 15; остальные 15 — не отношения рисков (средняя разность, AUC, чувствительность) |
| **оценка полноты по отношениям рисков** | **≈ 0,94** |

Проверка «оценка внутри своего интервала» в отчёт не идёт: код сам отбрасывает такие
случаи, и 100 % там ничего не значат.

**Метки.** Иногда стоит общая метка, «HR» вместо «aHR» или «OR» вместо «aOR». Число при
этом верно.

**Основные пропуски** (кандидаты для закрытого списка, не сделаны):
- «risk ratio» в 4 из 15;
- «AOR» заглавными в 2;
- «prevalence ratio», «rate ratio», «pooled HR»;
- «hazards ratio»;
- интервал с верхней границей ≥ 500 (OR 37,96, ДИ 3,57–543,90): его отсекает правило против годов.
